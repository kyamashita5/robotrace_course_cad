# NTF Robotrace Course Archive

Use this skill only to discover, inventory, verify, and download Robotrace course drawing images published in the official New Technology Foundation (NTF) Micromouse archive.

## Official Entry Points

Start from official navigation rather than guessing image filenames:

- Past activities and contests: `https://www.ntf.or.jp/?page_id=333`
- Historical maze collection: `https://www.ntf.or.jp/mouse/history/index.html`
- Example annual page: `https://www.ntf.or.jp/mouse/micromouse2024/maze.html`

The annual page layouts currently follow two main patterns:

```text
2011-2019: https://www.ntf.or.jp/mouse/micromouseYYYY/maze/maze.html
2020 onward: https://www.ntf.or.jp/mouse/micromouseYYYY/maze.html
```

Treat these as discovery hints, not guarantees. Prefer links found in official archive pages and adjacent-year navigation. Do not probe speculative image filenames.

## Inventory Workflow

### 1. Determine the requested scope

Identify whether the user wants:

- one year
- a year range
- all currently available years
- an inventory only
- actual local downloads

If actual downloads are requested without a year or range, ask one short question before downloading. An inventory request does not authorize downloading all images.

### 2. Discover annual pages

Fetch the official archive entry page and follow its annual links. For older pages, also follow the previous-year and next-year links at the bottom of an annual maze page.

Use the known annual URL patterns only to fill gaps in official navigation. A `404` at `/maze.html` does not prove that the year is unavailable; check `/maze/maze.html` for 2011 through 2019.

Stop following older pages when official navigation no longer provides an annual task-list link and both known annual page patterns return `404`. Record this as "annual Robotrace drawing page not found," not as proof that no Robotrace event occurred.

### 3. Identify Robotrace entries from page context

Read the annual page as HTML or Markdown and associate each image link with the surrounding competition label.

Include only links under a visible `ロボトレース競技` heading. Exclude:

- `マイクロマウス競技`
- `クラシックマウス競技`
- `支部サーキット競技`
- canceled events with links only inside HTML comments
- entries marked as data pending or without an image link

Do not classify images by `_RT` in the filename alone. The surrounding page heading is authoritative.

Use the anchor `href` as the full-size image URL. Do not use the nested `<img src>` because it may point to a smaller `*_RTs` thumbnail or include a cache-busting query string.

Resolve relative links against the annual page URL. Preserve subdirectories such as `Local/`, `AllJapan/`, and `robots/`.

Known naming variations include:

- `_RT.png`, `_RT.jpg`, and year-level names such as `MM2024RT.png`
- `kyusyu` and `kyushu`
- `student` and `students`
- thumbnail names ending in `_RTs`

Never reconstruct a URL from these examples when an exact `href` is available.

### 4. Rebuild the full snapshot

When the user asks to rebuild the full availability table, regenerate it from the official annual pages instead of copying the checked-in table:

1. Start a monotonic timer for annual-page discovery and extraction.
2. Fetch each annual source page once, using official navigation and the known old/new page patterns.
3. Ignore HTML comments, then associate every visible `ロボトレース競技` block with its containing event heading and full-size anchor `href`.
4. Resolve each `href` to an absolute URL and record `(year, event category, event name, source page URL, image URL, file format)`.
5. Classify event headings into the snapshot columns. Treat an explicitly labeled All Japan preliminary as `全日本予選`, the ordinary All Japan image as `全日本`, and the 2018 East Japan record meeting as `東日本記録会`.
6. Require at most one image per `(year, event category)`. Report duplicates or unclassified Robotrace links instead of silently choosing one.
7. Render available cells as `[✓](full-size-image-URL)`, leave unavailable cells blank, and calculate row, column, and grand totals.
8. Stop the discovery timer. Compare the rebuilt records with the checked-in snapshot by `(year, event category, image URL)` and report added, removed, URL-changed, duplicate, and unclassified entries.

Use this column order when rendering: `全日本`, `全日本予選`, `東日本`, `全日本学生`, `関西`, `中部初級者`, `中部`, `九州`, `北陸信越`, `東北`, `金沢草の根`, `東日本記録会`.

Page extraction confirms what the official annual pages currently list; it does not prove that every image target currently returns `200`. Only perform the separate live-verification phase below when explicitly requested. Time that phase separately so the report distinguishes table rebuild time from image-server verification time.

### 5. Verify current availability

Do not send a `HEAD` request for every discovered image during an ordinary inventory. Reuse the verified snapshot above and information from the annual source pages. Perform live image checks only when the user explicitly requests verification, and only for the requested years or images.

Apply these rules to all requests to NTF during page discovery, `HEAD` verification, or `GET` download:

- use a host-scoped queue with at most two requests in flight to `www.ntf.or.jp`
- space request starts by at least 500 milliseconds; do not launch the whole queue at once
- reuse a valid local file or a result already obtained in the current task
- when revalidating an existing file, use its stored `ETag` or `Last-Modified` value with `If-None-Match` or `If-Modified-Since`
- do not send `HEAD` before a requested download; validate that image from its `GET` response
- on the first `403` or `429`, stop launching requests, cancel queued work, record `Retry-After` when present, and do not resume automatically
- on a timeout or `5xx`, reduce concurrency to one and use exponential backoff with jitter; stop after two consecutive failures
- do not repeatedly retry a failing URL or bypass access controls

For each image the user explicitly asks to verify without downloading, perform one low-cost check that follows redirects. Confirm:

- an unconditional request returns `200`
- a conditional request for an existing valid local file returns `200` or `304 Not Modified`
- `Content-Type` starts with `image/` when the response is `200`; a `304` may omit representation headers
- the final URL remains on an expected NTF host

Example:

```bash
curl -I -L "https://www.ntf.or.jp/mouse/micromouse2024/MM2024_kansai_RT.png"
```

Treat `304 Not Modified` as successful verification only when the corresponding local file exists and is valid. Keep that file unchanged and do not send an unconditional follow-up request. If there is no valid local file, a `304` cannot satisfy the request and must be reported as a cache-state error.

If a server does not support `HEAD`, report the image as not live-verified. Do not fall back to `GET` unless the user requested a download. Record `403`, `404`, `429`, and `5xx` responses separately.

Report inventory results with at least:

- year
- event name
- annual source-page URL
- full-size image URL
- file format
- availability status

Distinguish missing images, canceled events, and broken links from one another.

## Download Workflow

Download only the years or images explicitly requested by the user. From the repository root, use:

```text
data/ntf_robotrace_archive/<year>/
```

The repository's `data/` directory is ignored by Git. Do not stage, commit, package, or redistribute downloaded images.

Before creating a year directory, verify that `data/ntf_robotrace_archive/` is the intended local destination. Preserve the extension from the full-size URL and use a stable filename derived from the exact linked filename. Reject path traversal and do not allow a URL to choose directories.

For a first-time individual download when the destination file does not yet exist:

```bash
curl --fail --location --remote-time \
  --user-agent "robotrace-course-cad archive downloader" \
  --output "data/ntf_robotrace_archive/2024/MM2024_kansai_RT.png" \
  "https://www.ntf.or.jp/mouse/micromouse2024/MM2024_kansai_RT.png"
```

For multiple images:

- apply the live-request rules from the verification section
- validate final status, `Content-Type`, and final host from each download response
- write a `200` response body to a temporary file, validate it, and only then replace the destination file
- on `304 Not Modified`, discard any empty temporary output and retain the existing local file unchanged
- reuse existing valid files instead of downloading them again
- do not bypass access controls or anti-automation measures

Write or update a local `manifest.json` in the download root. Each image entry should contain:

```json
{
  "year": 2024,
  "event_name": "2024年度マイクロマウス関西地区大会",
  "competition": "ロボトレース競技",
  "source_page_url": "https://www.ntf.or.jp/mouse/micromouse2024/maze.html",
  "image_url": "https://www.ntf.or.jp/mouse/micromouse2024/MM2024_kansai_RT.png",
  "local_path": "2024/MM2024_kansai_RT.png",
  "content_type": "image/png",
  "etag": "<ETag response header when present>",
  "last_modified": "<Last-Modified response header when present>",
  "downloaded_at": "<ISO-8601 timestamp>"
}
```

Do not put image bytes, base64 data, cookies, tokens, or unrelated page content in the manifest.

## Copyright and Site-Care Rules

NTF pages display `All Rights Reserved`, and no general open-data license for these course images was found during the 2026-07-18 review. Direct image links support ordinary viewing, but they do not by themselves grant redistribution rights.

Follow these rules:

- keep downloaded images local
- do not add source images, thumbnails, or copied page images to Git
- record the official source page and image URL
- do not imply NTF endorsement or affiliation
- do not automatically download during installation, import, tests, or CI
- do not mirror the archive
- do not treat a missing `robots.txt` as permission
- use explicit user selection, caching, bounded host-level concurrency, and paced request starts

If the user asks to publish, redistribute, bundle, or build a public image dataset, stop and explain that permission from NTF or legal review may be needed. Do not present this skill as legal advice.

## Final Report

After inventory or download, report:

- requested and checked year range
- annual pages found and missing
- Robotrace image count by year
- successfully verified or downloaded count
- canceled, unpublished, broken, or failed entries
- local destination and manifest path, when downloads were requested
- official source URLs

For a full snapshot rebuild, also report:

- annual-page `GET` and image `HEAD` request counts
- annual-page discovery/extraction time and live-verification time separately
- added, removed, URL-changed, duplicate, and unclassified entries versus the checked-in snapshot
- HTTP status, invalid `Content-Type`, unexpected final host, and timeout/error counts

State the access date because archive availability can change.
